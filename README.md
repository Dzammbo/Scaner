# Анализ предложений беттеров и дневник исходов

## Назначение репозитория

Этот репозиторий используется исключительно для:

1. независимого анализа спортивных исходов, предложенных беттерами;
2. ведения «Дневника исходов»;
3. расчёта и анализа всех записей дневника, включая общую статистику и разрезы;
4. ручного отбора футбольных матчей на ТБ по согласованным прематчевым и live-сценариям без балльных порогов.

Любые прежние задачи автоматического Scanner, Mining, S30, live-сигналов, forward-тестов и исследования автоматических стратегий исключены из активного `main`.

## Источник истины

- Каноническая ветка: `main`.
- Канонический дневник исходов пользователя: `Дневник исходов/Дневник исходов.xlsx`.
- Отдельный дневник прогнозов Джарвиса: `Live ТБ/Live ТБ.xlsx`. Текущий режим содержит один «Основной» прогноз на матч; исторические контуры «Оптимальный» и «Агрессивный» сохранены без пересмотра.
- Правила анализа беттеров: `docs/Канон анализа предложений беттеров.md`.
- Правила ведения и анализа дневника: `docs/Канон дневника и анализа записей.md`.
- Правила отбора футбольных ТБ: `docs/Канон отбора футбольных матчей на ТБ.md`.

Копия дневника в ChatGPT Library используется как рабочая пользовательская версия. После каждого изменения дневника версии в репозитории и Library должны быть синхронизированы. При расхождении сначала проверить дату и версию; без подтверждения не объединять данные автоматически.

## Команды

### «Оцени»

Провести независимый анализ каждого предложенного исхода по канону. Не принимать мнение беттера за исходную гипотезу. Сначала оценить спортивную составляющую, затем цену и альтернативы.

### «Добавь в дневник»

Внести новую запись в канонический дневник. Сначала проверить номер, дату, турнир, матч, рынок, коэффициент, сумму, тип Live/прематч и статус. При критичной неоднозначности запросить уточнение.

### «Обнови дневник» / «Рассчитай результаты»

Проверить незакрытые записи, внести фактические результаты и пересчитать связанные итоги. Не изменять исходные условия записи задним числом.

### «Проанализируй дневник»

Провести анализ всей актуальной выборки или указанного периода. Разделять факты, расчёты и выводы. Показывать размер выборки и не выдавать малые разрезы за устойчивую закономерность.

### «Найди верховые матчи» / «Проведи полный анализ по гипотезам»

Применить канон отбора футбольных матчей на ТБ к широкому списку или конкретному матчу по названию, ссылке или скриншоту. Объяснить голевой сценарий, аргументы против и полноту данных. Отдельно оценить конкретную линию и цену до матча либо условия повторной проверки в live. Баллы, обязательное совпадение всех признаков и закрытый прематчевый список не использовать. Результаты выдавать текстом в чате. Фоновое наблюдение и автоматические сигналы эта команда не запускает.

### «live»

Получить свежий снимок доступных футбольных матчей через BetsAPI Events API и провести ручной отбор по канону ТБ. Предварительный список и финальный топ-5 формировать исключительно по спортивным признакам, без влияния линии и коэффициента на попадание матча в топ. Для каждого кандидата показать страну, лигу и обе команды по-русски, минуту, счёт, основную линию тотала матча из Events, коэффициент, необходимое число дополнительных голов, сценарий, аргументы за и против. После спортивного решения отдельно заключить: основная линия оправдана либо лучше по возможности выбрать более низкий тотал. Балльный порог не использовать.

Events API используется для общего списка, минуты, счёта, накопленной статистики и одной свежей основной линии тотала матча. После спортивного первичного прохода не более 15 кандидатов параллельно обогащаются через `event/stats_trend`, из которого рассчитывается динамика за 5, 10 и 15 минут. Полный Bet365 API и альтернативные линии в текущем процессе не используются. Если основной тотал Events требует больше двух дополнительных голов для полного выигрыша либо не соответствует спортивному сценарию, матч не исключать из топа, но рекомендовать более низкий тотал без выдумывания его коэффициента.

В начале ответа обязательно показывать воронку снимка: **всего матчей в live-окне / допущено к содержательному анализу / обогащено поминутной динамикой / выбрано ПОДХОДИТ В LIVE**. Рабочее окно автоматической команды: **8-60-я минута включительно**. Женский, молодёжный, юниорский и резервный футбол не исключать; категорию каждого матча обозначать отдельно. Конкретный матч после 60-й минуты анализировать только по отдельному запросу пользователя. Технический защитный предел сбора - 100 матчей за запуск; при его достижении явно сообщать об ограничении. Анализировать весь доступный пул, углублять максимум 15 предварительных кандидатов и выводить только топ-5 наиболее подходящих без искусственного добора.

Показать быстрый текст с максимум пятью кандидатами, спортивной статистикой, основной линией Events как ориентиром и отдельным заключением по линии. Один матч показывается в основном топе только один раз: его ID фиксируется в `.github/live-selected-events.json` и исключается из последующих обычных full-проходов. Повторный разбор допускается только по прямому запросу пользователя через refresh. С 14.10.2026 live не читает и не обновляет Excel, не проверяет прежние результаты и не синхронизирует дневник. Сохранение API-снимка для динамики остаётся автоматическим. Постоянного фонового наблюдения нет.

### «Обнови дневник live»

По отдельной команде пакетно обновить `Live ТБ/Live ТБ.xlsx`: перенести ещё не внесённые показанные основные прогнозы, по одной условной единице каждый, и рассчитать подтверждённые результаты прежних записей. Исторические строки двух контуров не изменять. Брать предложения и исходные цены из ответов в чате, сверять условия с сохранёнными снимками и проверять дубли. Снимок всего пула не заменяет список реально предложенных вариантов. Если исходные ответы недоступны, обозначить пробел и запросить их, не реконструируя предложения задним числом. После изменения синхронизировать книгу в репозитории и Library. Команда «рассчитай результаты live» отдельно запускает проверку результатов Live ТБ.

Основной `Дневник исходов/Дневник исходов.xlsx` вести отдельно только по фактическим выборам пользователя; его не менять при обновлении Live ТБ. Исторические контуры сравнивать отдельно от текущего режима «Основной». Исторические 53 live-прогноза и исходный итоговый отчёт за 13.10.2026 сохранены; отдельный дневник прематча не восстанавливается.

### Уточнение быстрого live от 15.10.2026

Первичный ответ остаётся быстрым: один общий API-снимок, предварительный список максимум из 15 событий, параллельное получение их `event/stats_trend` и до пяти обоснованных кандидатов. Внешний поиск не обязателен: после первичного ответа проверяются максимум 1-3 матча с конкретным существенным сомнением, параллельно, с общим бюджетом 20-30 секунд. Перед дополнением обязательно обновляются счёт и активные линии только этих матчей. При задержке свежие данные не подменяются старыми.

Снимки каждого вызова сохраняются в `snapshots/live/`; повторные матчи дополнительно получают динамику за фактический интервал между снимками. Основная свежая динамика предварительных кандидатов берётся из поминутного `event/stats_trend`, поэтому она доступна и при первом снимке события. Пропуски и исправления счётчиков не превращаются в нули или ложные изменения. Сохранение истории не блокирует первый ответ; работа с дневником выполняется только отдельной командой.

Запуск: workflow_dispatch либо свежий `.github/live-request.json` (`full` или `refresh`, для refresh максимум три ID). Сбор не запускается от обычных изменений кода/дневника и не работает по расписанию. Подробности, ограничения и порядок проверки эффективности закреплены в каноне отбора ТБ.

## Жёсткие границы

В активном `main` запрещено использовать или восстанавливать без отдельной команды пользователя:

- автоматический Scanner и его стратегии;
- Mining, S30 и прежние live-коллекторы;
- технические коды старых стратегий;
- forward-log и reverse-анализ прежних систем;
- старые квоты API, бюджеты запросов и расписания;
- исторические правила отбора сигналов;
- содержимое архивной ветки как действующий канон.

Прежний проект сохранён в ветке `archive/legacy-scanner-2026-10-12`. Эта ветка является только архивом и не должна читаться для текущих задач, если пользователь прямо не попросил поднять исторические данные.

## Общие правила

- Мы ищем систему и проверяем гипотезы, а не обещаем прибыль.
- В пользовательских отчётах использовать понятные русские названия.
- Для каждого матча обязательно указывать турнир.
- Актуальные данные и первоисточники имеют приоритет над памятью и старыми чатами.
- Не смешивать результаты разных правил, периодов или типов записей без явного сопоставления.
- Не менять канон или структуру дневника автоматически из-за единичного результата.
