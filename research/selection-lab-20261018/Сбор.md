# Независимый сбор при Live

По согласованию 18.10.2026 команда Live запускает рабочий и экспериментальный сборы. Экспериментальные данные не заменяют рабочую рекомендацию и не записываются как пользовательские публикации.

Рабочий workflow на main остаётся прежним. Второй самостоятельный workflow запускается тем же push .github/live-request.json, получает только исходный запрос и его main SHA, затем использует код ветки research/selection-lab-20261018. Он не зависит от завершения или успеха рабочего workflow. Своих данных из main не читает: отдельный inplay, тренды, профили, котировки, кэш и журнал. Одинаковые ID могут быть в обоих контурах; выбор одного не исключает матч из другого. Каждый экспериментальный вариант исключает только собственные прошлые выборы. Повторные сырые наблюдения продолжают сохраняться для исследования.

Параметры: до 60 кандидатов с глубокими данными, 4 параллельных запроса; цены для первых 20 сильных и до 10 контролей; максимум 240 запросов API на весь запуск, резерв 200 известных оставшихся запросов для рабочего контура. Контроли: до пяти не прошедших сильный допуск внутри первых 30 и до пяти на местах 31–60. Псевдослучайный выбор воспроизводим по SHA запроса; размер группы и вероятность включения сохранены. Матчи за первыми 60 видны в исходном пуле, но не получают тренды автоматически.

Сохранены спортивный базовый вариант, точная цена канонического тотала, ограничения нужных голов ≤2/≤3, базовый вероятностный прототип с EV≥0,05. Каждая группа 0–5, без квоты, только исследовательские выборы. Варианты не объявлены улучшением Live. Для модели используется ранее зафиксированная историческая обучающая база только предыдущих московских дней; автоматически собранные новые исходы сами по себе её не переобучают.

Все доступные ответы котировок сохраняются для будущего разбора. Известность цены не гарантируется: при четвертичной исходной линии требуется цена именно сниженного на 0,25 тотала; исходная цена не переносится. Олимп не проверяется. Сохраняются времена каждого источника, связь с командой, SHA кода, причины недопуска, расходы API. В снимке base-поля final_sports_* только диагностика базового спортивного шага; канонические экспериментальные выборы — experimental_choices и отдельный receipt.

На следующих Live после свежего экспериментального снимка дополнительно проверяются до 20 старых нерассчитанных целей, отобранных на прошлых проходах. Минимум 2 часа после снимка, минимум 30 минут между проверками. Для закрытия нужны ID события, FT scores.2, статус завершения и непротиворечивый счёт/идентичность команд. Неизвестные результаты и конфликты остаются неизвестными. Очередь и отложенные исходы сохранены; это не обещание расчёта всех матчей после одного Live. Голы относительно снимка не считаются выигрышами фактического входа пользователя.

Файлы только в исследовательской ветке:

- research/live-lab/snapshots/<run>-<attempt>.json
- research/live-lab/receipts/<run>-<attempt>.json
- research/live-lab/outcomes/<run>-<attempt>.json

Сохранение идёт отдельным коммитом в research/selection-lab-20261018; main и рабочие журналы не переписываются. GitHub artifact служит дополнительной копией, срок 30 дней. Здесь описан ручной канал. Дополнительно действует отдельный непрерывный фон с интервалом 10 минут и своими журналами; см. Фон.md. Refresh рабочего контура не запускает новый экспериментальный отбор.

Сборы независимы логически, но источник, подписка API и инфраструктура GitHub общие. Поэтому нельзя обещать полную независимость задержек: задача исследования не блокирует выдачу основного списка, однако общий лимит API/очередь GitHub остаются общим ресурсом. При недостатке квоты эксперимент ограничивается или падает отдельно; это не превращает рабочий список в пустой. Частичные и неуспешные сборы явно помечаются, не выдаются за отсутствие подходящих матчей.

Сравнение контуров делается по связи request SHA + ID события с учётом собственных времён снимков и цен. Разные моменты наблюдения и разные журналы исключений не позволяют автоматически приписывать всю разницу правилам отбора. Подтверждающая проверка новых вариантов требует нового периода и контроля полноты.

Проверка: test_capture.py выполняет изолированный прогон с имитацией API, проверяет собственные пути/журналы, сохранение котировок, бюджет, контрольную выборку и отсутствие подмены неизвестных FT. test_lab.py отдельно проверяет финансовую математику. Реальный вызов API при настройке не выполняется; первый сетевой сбор произойдёт по следующей команде Live.
