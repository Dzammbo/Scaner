# Непрерывный фоновый сбор двух контуров

Согласовано 18.10.2026: интервал 10 минут, без суточного лимита, до ручной остановки. Это GitHub Actions, без вызова ChatGPT и без сообщений в чат. Рабочая команда Live остаётся самостоятельным свежим запросом.

Планировщик main: .github/workflows/live-background.yml, минуты 03,13,23,33,43,53 каждого часа UTC (минуты по Москве те же). GitHub cron работает best effort: задержки и пропущенные запуски возможны. Это до 144 циклов/сутки, не гарантия точного таймера.

Два независимых matrix job, fail-fast=false. Каждая задача делает свой inplay, тренды, историю и цены через код исследовательской ветки. Общий cycle ID связывает их, а реальные времена источников сохраняются. Рабочая версия спортивного допуска и порядок не изменены. Версии и SHA каждого сбора записаны. Совпадающий ID в двух контурах допустим; ошибки одного не отменяют другой.

Фоновый primary: 30 кандидатов с глубокими данными, текущий сильный допуск, 0–5 в спортивном порядке, цены первых пяти. Исключает только собственные фоновые прошлые выборы перед предварительным Top-30. Бюджет 120 запросов на цикл, включая до 20 проверок прежних исходов.

Фоновый experimental: до 60 глубоких кандидатов; до 20 сильных с запросом рынков и до 10 стратифицированных контролей; пять ранее зафиксированных вариантов отбора с собственными исключениями. Бюджет 240 запросов на цикл, включая до 20 проверок прежних исходов. Модель не переобучается автоматически на новых исходах; текущая seed-база и условия зафиксированы. Ни один вариант автоматически не заменяет рабочий Live.

Максимум двух фоновых бюджетов 360 запросов/цикл, 2160/час при шести циклах. Это защитный верхний предел, фактический расход обычно ниже за счёт размера пула и кэша. Ручные запросы и другие проекты добавляются отдельно. При известном остатке API ≤200 новые фоновые обращения блокируются. При активном/ожидающем ручном workflow либо ручном запросе последних 90 секунд фоновая задача пропускается ещё до BetsAPI. Ручной запрос, возникший после проверки приоритета, может пересечься со сбором; полной изоляции общей подписки/очереди GitHub нет.

Фон не пишет в snapshots/live, .github/live-selected-events.json, .github/live-publications или Excel. Ручные публикации не импортируются в фоновые исключения. Фоновые выборы не являются публикациями пользователю и не исключают матч из ручного Live. Каждый источник помечен source=manual/background, contour и data_scope. Не складывать повторные снимки одного ID в независимое N.

Хранение в ветке research/selection-lab-20261018:

- research/live-background/primary/{snapshots,receipts,outcomes}/YYYY-MM-DD/<run>-<attempt>.json.gz
- research/live-background/experimental/{snapshots,receipts,outcomes}/YYYY-MM-DD/<run>-<attempt>.json.gz

Дата каталогов по Москве. Сжатие gzip без удаления полей. В автоматическом исследовательском контуре сохраняются основной тотал BetsAPI и его точный коэффициент без изменения линии; цены запрашиваются по всему доступному пулу с целевым покрытием выше 95%. Фактическое покрытие фиксируется в каждом снимке, отсутствующие цены не восполняются. Для кэша внутри runner распаковываются последние 50 только собственных снимков. GitHub artifacts дополнительно хранятся 30 дней; канонические файлы ветки автоматически не удаляются. Размер архивов и время checkout требуют контроля при длительном накоплении; постоянное хранение всей истории неизбежно увеличивает репозиторий.

На каждом цикле после свежего сбора проверяется ограниченная очередь прежних целей. Первая проверка результата начинается через 1 час после первого наблюдения, повторная проверка незакрытого матча - минимум через 30 минут. Нужны завершение, scores.2 и совместимые команды/счёт. Очередь нерассчитанных и ошибки сохраняются. Количество кадров не заменяет количество закрытых уникальных матчей. Исход относительно снимка не является результатом реального входа пользователя; фактическая доступность Олимпа не утверждается.

Остановка: по команде пользователя enabled=false в .github/live-background.json и удаление schedule из live-background.yml. Это останавливает и сбор, и периодическое создание runner. Автоматического expires_at нет. Ручные Live и их экспериментальный сбор остаются работающими. При возобновлении восстанавливаются enabled и расписание.

Техническая проверка: test_background.py — три проверки схем, сжатия, восстановления кэша и собственного исключающего журнала; test_capture.py — семь проверок независимого сборщика; test_lab.py — семь проверок финансовой математики и ретроспективы. Main gate проверяется отдельно тремя тестами. Сетевой запуск и фактическое сохранение проверяются после публикации конфигурации.
