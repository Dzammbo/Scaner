# Общий фоновый сбор и раздельные оценки

Согласовано 18.10.2026. Режим shared_background_v1 заменяет два физических фоновых сборщика. Один job каждые 10 минут до ручной остановки; в чат ничего автоматически не отправляется. Задержки расписания GitHub возможны. Ручной Live и его публикации остаются отдельными.

Один свежий inplay на цикл. Исследование выбирает до 60 новых ID по фазам и счетам, исключая только прежние глубокие исследовательские входы. Не выбранные ранее ID остаются кандидатами. Контроль действующих правил отдельно формирует свои прежние Top-30 в окне 8–60, исключая только собственные прежние выборы. Объединение этих наборов по ID получает по одному запросу тренда и рынков на матч; профиль обогащается общей стадией с кэшем. Пересекающиеся кандидаты не дублируют запросы.

Исследовательский глубокий вход повторно не создаётся. При необходимости текущей оценки контрольного кандидата его подробности могут обновляться: это контрольное наблюдение, не новый исследовательский вход и не новый уникальный матч. Контроль не должен считать прежний тренд свежим. До 90 разных подробных событий за цикл, максимум 360 физических API-вызовов (не больше прежней суммы 120+240), резерв 200 сохранён. Фактические вызовы считаются один раз; доли экономии без сопоставимого контрольного замера не выдумываются.

Один архив снимков/квитанций/исходов продолжает существующий путь research/live-background/experimental. collection_mode=shared_background_v1 и independent_board=false отличают новую схему. Старый research/live-background/primary сохранён неизменным, его выборы продолжают контрольный реестр, незакрытые исходы переходят в общую очередь. Контрольные решения находятся в control_evaluation, исследовательские варианты в experimental_choices (в квитанции choices). Правила и реестры решений раздельные, данные общие: это не две независимые статистические выборки. Основные .github/live-selected-events.json и .github/live-publications не читаются для исследовательских исключений и не меняются.

Контроль сохраняет полный список своих кандидатов, оценки достаточности данных, причины отказа, число сильных и выборы 0–5. Неизвестные/неполные данные не объявляются проигрышем или доказательством слабого матча. Цена относится к реальному времени её получения; изменение счёта и неподтверждённая цена учитываются прежними проверками. Итоговые данные не используются как признаки прошлого.

Отчёт только по запросу пользователя: период и время последнего снимка по Москве; прошедшие/частичные/ошибочные циклы; уникальные матчи базы; новые исследовательские входы за период; реально доступные тренды и точные цены; закрытые и ожидающие исхода; отдельно выборы действующих правил и каждого исследовательского варианта. Условный ROI показывать только с N закрытых наблюдений с подтверждённой ценой, отдельно от голевой проходимости. Не складывать повторные снимки и пересечения оценок в независимое N. Различать версии до/после объединения. По умолчанию краткий текст без списка всех матчей, подробности по запросу.

Экспериментальные оценки используют все свежие обогащённые данные объединения в своём окне 8–60, включая контрольные обновления: experimental_evaluation_event_ids. Их нельзя ограничивать только новыми исследовательскими входами, иначе при отсутствии новых ID возникнут искусственные нули. Контроль по-прежнему оценивает собственный Top-30. Новые входы, оценённые кандидатуры и выборы — разные показатели.
