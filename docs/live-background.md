# Фоновый сбор primary и experimental

Согласовано 18.10.2026: каждые 10 минут, без срока окончания, до ручной остановки. Ручная команда Live и отдельный экспериментальный сбор по ней остаются работающими.

Workflow live-background.yml запускает два независимых job без чата. Код и данные — ветка research/selection-lab-20261018. Основной фон: глубина 30, рабочий сильный допуск и спортивный порядок 0–5, собственные исключения; экспериментальный: глубина до 60, сильные и контрольные кандидаты, ранее зафиксированные варианты. Исходы проверяются на последующих циклах с ограниченной очередью. Правила автоматически не оптимизируются.

Конфигурация .github/live-background.json: enabled=true, interval_minutes=10, stop_policy=manual_only. Суточного отключения нет. Cron — минуты 03,13,23,33,43,53; это целевой интервал, GitHub может задержать/пропустить запуск.

Новые фоновые сборы пропускаются при активном ручном workflow или свежем ручном запросе последних 90 секунд. Бюджеты API 120 для primary и 240 для experimental на цикл, включая проверки исходов; максимум 2160/час при шести циклах, без ручных и прочих проектов. Резерв 200 известных оставшихся запросов. Общая подписка API и очередь GitHub остаются общим ресурсом; абсолютная независимость задержек не обещается.

Все полученные данные сохраняются gzip в research/live-background/<scope>/{snapshots,receipts,outcomes}/YYYY-MM-DD/<run>-<attempt>.json.gz в исследовательской ветке. Автоматического удаления канонических данных нет. Сжатые файлы организованы по московским дням; исходы неизвестных матчей не считаются проигрышами. GitHub artifacts дополнительно хранятся 30 дней.

Фоновые выборы НЕ писать в .github/live-selected-events.json, .github/live-publications или Excel. Они НЕ исключают матч из ручного Live. Source manual/background и contour учитываются при анализе. Снимки одного матча не увеличивают независимое N; сравнение учитывает разницу времени и цены.

Остановить по команде пользователя: enabled=false и удалить on.schedule из live-background.yml. Ручные workflows не отключать. Возобновление — обратное изменение. Управление и реализация: research/selection-lab-20261018/Фон.md в исследовательской ветке.
