# Голевой профиль Live v7

Согласовано 16.10.2026. Версия sports-only-2026-10-16-v7. Механика v6 сохранена, кроме явно описанного исторического дополнения. Эффективность ещё не доказана.

## Источники и расчёт

После широкого Top-30 параллельно внутри отдельной ограниченной стадии: /v1/event/history qty=20 на каждый новый матч; /v3/events/ended sport_id=1 league_id=... page=1 на каждую уникальную лигу без кэша. Хранить командные ID, ID лиги и старт из общего ответа. Не угадывать идентичность по названиям. Время истории строго раньше старта текущего матча; только завершённые, уникальные ID, максимум 20 последних. Лига: до 50 доступных матчей первой страницы до старта, не полный сезон и не гарантия ровно 50.

Считать по сторонам средние забитые, пропущенные, суммарные голы, количества 0–1/2/3+ голов и ТБ 1,5; последние 10 отдельно, домашние хозяев / выездные гостей отдельно. Второй тайм = FT минус HT только при наличии согласованных периодов. У каждого показателя свой N. Предпочитать scores.2; при отсутствии допустим ss с явной пометкой непроверенного периода. При обнаруженном дополнительном времени/пенальти или кубковом названии без scores.2 строку не использовать. Это ограничение качества исторических счетов, не исключение текущей категории.

## Порядок финала

1. Прежний класс Live-доказательств.
2. Прежнее минимальное окно подтверждения 5/10/15 минут.
3. Историческое отношение: ((забитые хозяев + пропущенные гостей + забитые гостей + пропущенные хозяев) / 2) / средний тотал лиги. Только матчи той же лиги; по каждой команде минимум 5, по лиге минимум 10. Более высокое отношение раньше. Это описательный показатель среды, не модель ожидаемых голов текущего матча.
4. Прежний порядок интенсивности: в створ, завершения, двусторонние завершения, опасные атаки, ID.

Неизвестный или недостаточно покрытый профиль нейтрален (отношение для сортировки 1, фактическая статистика остаётся неизвестной). Это не проходной балл, не сумма весов и не запрет низовых матчей. Малые выборки могут шуметь, поэтому пригодность изменения проверяется на новых данных. История не спасает матч без текущих Live-оснований. Состав и ранг формирует код; порядок показа по счёту не изменён.

## Скорость и хранение

История и база лиги сохраняются в снимках, повторный вызов читает до 50 последних файлов. Кэш до 24 часов; история события повторно используется только при совпадении ID обеих команд и времени старта. Кэш лиги повторно фильтруется по времени старта нового события. Нет фоновых запросов. Стадия профиля имеет бюджет запуска задач 8 секунд, сетевой таймаут истории команд до 5 секунд, лиги до оставшегося общего бюджета (не более 8 секунд), до 16 работников; задачи, не начавшиеся до дедлайна, пропускаются. Сетевой таймаут не обещает жёсткую общую задержку при медленной передаче тела ответа. Сбой истории не отменяет Live и не подменяется нулевой результативностью.

Бюджет полного прохода: 1 + N + H + L + K, где N<=30, H<=30, L<=30, K<=10. Максимум 101, до котировок 91. Реальные H/L и длительность истории сохраняются отдельно. Прежний benchmark v6 проверяет динамику/цены и не измеряет историю; не выдавать его за benchmark v7.

В финальной карточке: по каждой команде N, средние забитые/пропущенные, частота ТБ 1,5 и 3+; доступны домашние/выездные, второй тайм и база лиги с N. Если история или часть показателей отсутствует, написать причину. Сохранять профиль показанного матча также в техническом реестре. История не изменяет личные правила входа, дневники или прежние записи.

## Исправление загрузки 16.10.2026

Реальная диагностика: запрос лиги /v3/events/ended без day вернул 50 матчей за 7,339 секунды, прежний таймаут 5 секунд обрывал его. Запрос за один день быстрее, но не заменяет базу последних 50 матчей. Общий бюджет стадии 8 секунд не увеличен. Запросы истории и уникальных лиг чередуются, без хвоста из всех лиг после всех команд. Частичный кэш команд не блокирует повторную загрузку отсутствующей лиги; сравнение пересчитывается без повторного запроса команд и без продления возраста их истории. В снимке goal_profile_diagnostics различает успешный ответ, ошибку API/структуры, сетевую ошибку/HTTP-статус, таймаут и исчерпание бюджета. Тексты исключений и URL с ключом не сохраняются. Недостаточная история остаётся нейтральной; фильтры и формула ранжирования не менялись.

Проверка полного пула выявила конкуренцию медленных запросов лиг с историями команд. Исправлено резервированием: 8 работников для команд и 8 для лиг, суммарно прежние 16 и общий бюджет 8 секунд. Медленная лига не занимает слоты команд. При пустом кэше часть лиг всё ещё может не успеть; повторный вызов догружает только недостающие данные.
