# Формат команды «статистика» по умолчанию

Согласован 26.10.2026. Версия `statistics-two-tables-20261026-v2`. Этот документ имеет приоритет над прежними требованиями выдавать статистику списками, без таблиц или отдельными блоками каждого семейства. Он не меняет короткий ответ команды live, отбор, API-бюджет, журналы, условия и начало серий.

## Получение и выдача

По команде «статистика» выполнить свежий штатный пересчёт и дождаться сохранённого отчёта. Проверить ошибки всех разделов, а не только успешный статус workflow. Указать фактическое время среза и предыдущего полного отчёта по Москве. Не выдавать прежний отчёт за обновлённый. По отдельной просьбе лишь переформатировать данные новый пересчёт не запускать.

Канонический генератор: `.github/scripts/statistics_format.py`. Пересчёт сохраняет в JSON `statistics_format_version`, `statistics_tables`, `statistics_markdown`; рядом с JSON - такой же Markdown, в GitHub Actions summary и логе - тот же текст. Ассистент выводит готовые таблицы в чат, не заменяет их списком и не меняет порядок строк вручную. Для старого отчёта без этих полей разрешён локальный вызов:

```sh
python3 .github/scripts/statistics_format.py текущий.json --previous предыдущий.json
```

Отдельный файл пользователю не создавать без запроса.

## Ровно две таблицы

1. **Все ТБ - по убыванию ROI без трёх**. Контрольная пятёрка один раз; все действующие самостоятельные ТБ; ТБ отдельных сочетаний; все новые ТБ; контроль и кандидат эксперимента качества; широкий пул с котировками, справочно.
2. **Все ТМ - по убыванию ROI без трёх**. Все действующие самостоятельные ТМ и новые ТМ; будущие ТМ отдельных сочетаний также включаются сюда по полю рынка.

Названия по-русски, с пометками «Сочетание», «Новый», «Контроль», «Эксперимент», «справочно» там, где это различает группы. Число строк определяется текущими каталогами. Выключенные карманы не возвращать; прежние подмножества контрольной пятёрки и технические дубликаты `sports_v8_fresh` / `provider_main_total_exact` не выводить повторно. Архивные результаты - только по отдельному запросу.

| Группа | N (+новые) | ROI | ROI без 3 | Δ без 3, п.п. |
|---|---:|---:|---:|---:|
| Русское название ТБ | рассчитанные (+прирост) | ±X,XX% | ±Y,YY% | ±Z,ZZ |

Таблица ТМ содержит те же пять столбцов, включая последний заголовок **Δ без 3, п.п.** Проценты и изменения отображаются с двумя десятичными знаками и десятичной запятой, чтобы видеть небольшие изменения. N - завершённые валидные расчёты с исходной точной ценой, включая возвраты; открытые и неизвестные результаты исключены. Число всех выбранных не подставлять вместо N.

## Сортировка и динамика

- Обе таблицы сортировать глобально по ROI без трёх лучших по убыванию, независимо от семейства, статуса «новый» и обычного ROI.
- При N≤30 не показывать ROI без трёх, даже если исходный JSON его содержит. Такие строки ставить внизу по убыванию обычного ROI; неизвестный ROI - последним. В ячейках отсутствующих метрик писать «н/д». Числовые нули не использовать вместо отсутствующих данных.
- Δ ТБ и ТМ - изменение одного и того же показателя, ROI без трёх лучших. Это разность в процентных пунктах, не относительный процент роста. Объяснять это перед таблицами или сразу после них.
- N (+новые) сравнивается с последним сопоставимым полным отчётом. Начало серии с N=0 и отсутствующим ROI не является нулевым ROI: показывать «первый результат», а не придумывать прирост доходности. При N≤30 в текущем или предыдущем срезе сравнение ROI без трёх недоступно для обоих рынков, включая переход N=30 → 31.
- Смена серии или каталога не разрешает склеивать результаты автоматически. Для восстановленной истории требуется явно указанная преемственность каталога. Без сопоставимой базы Δ и прирост N - «н/д»/без скобок.
- Не скрывать ошибку раздела за пустой таблицей или отсутствием строк. Указывать её явно.

После таблиц кратко сохранять статус эксперимента качества, начало и число дней, прогноз и факт оставшихся голов. Всегда пояснять: группы пересекаются, N и ROI нельзя складывать; разные контрольные периоды и условия не делают сортировку доказательством превосходства метода. Малые выборки новых карманов не объявлять устойчивыми.

## Проверки

`test_statistics_format.py` проверяет объединение по рынкам, общий порядок, порог N=30/31, отсутствие дубликатов, единую метрику динамики обоих рынков, первый результат, несопоставимые каталоги, видимость ошибок и неизменность исходного отчёта. Workflow `verify-statistics-format.yml` запускает эти проверки и тесты сравнения отчётов.
