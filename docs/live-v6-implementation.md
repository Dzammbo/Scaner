Версия: `sports-only-2026-10-16-v6`. Это воспроизводимая эвристика спортивного отбора, не обученная модель вероятности и не доказанное финансовое преимущество.

## Исполнение

`live_snapshot.py` получает общий список, выбирает широкий Top-30 методом `single_snapshot_sports_queues_v4`, получает только динамику и формирует до пяти кандидатов методом `fresh_confirmed_threat_v2`. Линии и предпочтение 0:0 не участвуют в составе. Категории, окно 8–60 и лимит 30 сохранены.

После получения `LIVE_SNAPSHOT_JSON` со `stage=sports_ready` клиент сразу публикует список из `display_event_ids` и воронку. Не ждать завершения всего workflow или сохранения в git. Финальный ответ чата обязательно повторяет весь список; commentary не заменяет его. Код не может самостоятельно обеспечить время чтения логов и отправку сообщения ассистентом.

Отдельный следующий шаг `--odds-snapshot <path>` получает линии только финальных кандидатов, печатает `LIVE_ODDS_JSON` с тем же snapshot_id и отдельным временем проверки. Состав, спортивный ранг и исходное время снимка неизменны. Ошибки этого шага не отменяют спортивный результат. Сохранение в git выполняется после этих этапов; реестр выборов не изменяется сборщиком.

Бюджет: 1 общий запрос + до 30 рядов + до 5 линий = максимум 36. Спортивная готовность требует максимум 31 запрос. Параллельность до 16; сетевой таймаут 20 секунд не является гарантией времени всего вызова. Новых расписаний, подписок и массового веб-поиска нет.

## Точный приоритет финального списка

Последовательно сравниваются:

1. Класс подтверждения: (0) удар в створ, положительный прирост xG с завершением той же команды в том же интервале либо завершения в двух соседних непересекающихся интервалах; (1) опасные атаки с завершениями либо двусторонние завершения; (2) устойчивые опасные атаки с угловыми.
2. Самое короткое окно, подтверждающее этот класс: 5, затем 10, затем 15 минут. Один тихий отрезок не исключает матч, если есть подтверждение в более широком окне.
3. Темп известных попаданий в створ, темп известных завершений, абсолютное число завершений менее активной стороны, темп известных опасных атак. При полном равенстве event_id как строка.

Это лексикографический порядок без суммы баллов и квот маршрутов. Он меняет состав финала. Сильная односторонняя угроза допускается. Наличие поля xG само по себе не добавляет ранг; его величина не используется как преимущество над матчами без покрытия. Согласованный с завершениями положительный xG является свидетельством класса 0. Нулевой/неизвестный xG не блокирует остальные пути.

Полный показатель shots сохраняет единое определение on_target + off_target по известным сторонам. Отдельное finishing обозначает известные завершения, нижнюю границу при неполном покрытии; оно позволяет использовать известные off_target при отсутствующем on_target, не объявляя полное число ударов известным. Полный итог пары остаётся null, если одна сторона отсутствует. Для сортировки используются известные неотрицательные свидетельства; null в данных не переписывается нулём. Покрытие не даёт отдельного бонуса, но неизвестные факты невозможно восстановить: различие полноты остаётся ограничением сравнения.

## Время и смена контекста

Сохраняются исходные нормализованные ряды, исторические окна и отдельно `current_windows`. После последнего обнаруженного прироста goals/redcards текущее окно начинается не раньше точки, в которой изменение уже зафиксировано. Точный момент события по разреженному счётчику не известен, что отмечено явно. Отсутствие ряда goals/redcards не означает, что событий не было.

В перерыве текущая угроза не подтверждается историческими окнами. После начала второго тайма используются только точки после 45-й минуты. При наличии явного period используется он; без period минута >45 даёт помеченное предположение о втором тайме. Это не надёжная реконструкция добавленного времени первого тайма; вывод о фазе проверяется по доступному контексту, неопределённость не скрывается.

Для соседних окон нужны общая конечная граница, корректные начала и фактические длительности. На 8-й минуте предыдущий интервал 0–3 имеет длительность 3, не 5. Темп опасных атак сравнивается по тем же известным командам; сохраняются increasing/steady/fading/unknown. Само затухание не является запретом. Пересекающиеся окна не суммируются как независимые подтверждения. Прирост xG без завершения той же команды помечается как возможное рассогласование, не как доказанная ошибка источника.

## Контекст и учёт

Актуальный кэш `snapshots/prematch-latest.json` до суток используется только для сверки ID и команд, справочного контекста и порядка отправки запросов внутри уже выбранного спортивного Top-30. Никакого нового API-запроса или бонуса ранга. Просроченный/повреждённый необязательный кэш не блокирует live.

`final_sports_selection.rank` и `sports_rank` хранят спортивный порядок; `display_rank` в исторической v6 соответствовал группам счёта; с 18.10.2026 21:48 МСК новый показ следует строго спортивному рангу независимо от счёта. В реестре `rank` сохраняет прежнюю семантику порядка фактической выдачи; новые записи дополнительно содержат sports_rank/display_rank. Старые записи не переписываются.

Только `live_selection.py` по явно переданному списку фактически показанных выборов добавляет исключения. Даже технически выбранный финальный матч без публикации остаётся доступен следующему full. Весь Top-30 и оставшийся общий пул сохраняются для сравнения, но не становятся рекомендациями.

## Проверка качества и скорости

`python3 -m unittest discover -s tests -v` проверяет механику без API. `compare_live_ranking.py` сравнивает предварительные маршруты на сохранённых снимках, не оценивает проходимость.

`evaluate_live_pool.py --snapshots <файлы> --outcomes <JSON>` выполняет только офлайн-сравнение выбранных алгоритмом и невыбранных при одинаковых версии, пятиминутной группе, точном счёте, категории и доступности полей по сторонам. Исходы передаются явно по snapshot_id/event_id. Отдельно учитываются подтверждённые следующие 15 игровых минут и один/два гола до конца. Неизвестные исходы не становятся нулями; показываются знаменатели и зависимые повторы. Наличие сопоставимой контрольной группы отмечается отдельно. Нет автоматической подгонки правил, сбора результатов или доказательства причинности.

Явно запускаемый benchmark сравнивает один пул в порядке 30/15/15/30: сначала динамика, затем цены максимум пяти финальных кандидатов каждого этапа. Максимум 111 запрос. Время спортивной готовности и котировок раздельно. Проекция повторяет измеренные времена запросов и не выдаётся за замер нового пула; прежние измерения v5 к v6 не относятся.
